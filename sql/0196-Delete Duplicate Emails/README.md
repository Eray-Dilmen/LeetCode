# [196. Delete Duplicate Emails](https://leetcode.com/problems/delete-duplicate-emails/)

## Problem Description
Write a solution to delete all duplicate emails, keeping only one unique email with the smallest `id`. You are supposed to write a `DELETE` statement and not a `SELECT` one.

## Intuition
To keep only the unique email with the smallest `id`, we need to identify the "keepers" (the records we want to save) and delete everything else. By grouping the records by email, we can find the minimum `id` for each group. Any record whose `id` is not in this safe list of minimum `id`s is considered a duplicate and must be deleted.

---

## Approach: Subquery with NOT IN (Oracle / SQL Server)

### Explanation
This approach consists of two parts: identifying the records to keep and deleting the rest. 

**1. The "Keeper" List (Inner Query):** 
`SELECT MIN(id) FROM Person GROUP BY email`
* **Grouping:** The `GROUP BY email` clause logically groups rows that share the same email address into invisible "boxes".
* **Extracting Minimums:** The `MIN(id)` function dives into these grouped boxes and extracts only the smallest `id` value from each box.
* **Output:** The output of this subquery is not a textual summary (like "email - 2"), but rather a pure, flat list of numeric IDs (e.g., `1, 3, 4`). These are the IDs we want to keep.

**2. The Deletion Process (Outer Query):** 
`DELETE FROM Person WHERE id NOT IN (...)`
* **Scanning:** The database engine scans every single row in the `Person` table from top to bottom.
* **Checking and Deleting:** For each row, it checks if the row's `id` exists in the list generated by the inner query. If the `id` is **NOT IN** that safe list, it means this row is a duplicate, and it is permanently deleted.
* **Logic:** The deletion mechanism relies entirely on the `id` matching, rather than looking at the email strings again.

*(Note: While this syntax is perfectly valid in Oracle SQL and SQL Server, MySQL requires an additional wrapper query or a `JOIN` approach due to update restrictions on the target table).*

### Complexity
- **Time Complexity:** $\mathcal{O}(n)$ or $\mathcal{O}(n^2)$ depending on the database engine's optimization and indexing. Grouping takes $\mathcal{O}(n)$, and the `NOT IN` lookup can take up to $\mathcal{O}(n^2)$ if not indexed, but modern engines optimize this to $\mathcal{O}(n \log n)$ or better.
- **Space Complexity:** $\mathcal{O}(n)$
  - Memory is needed to store the temporary list of minimum `id`s returned by the subquery.

### Code
```sql
DELETE FROM Person 
WHERE id NOT IN (
    SELECT MIN(id)
    FROM Person
    GROUP BY email
);
```
